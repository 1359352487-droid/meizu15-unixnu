# 到"能日常使用的 iOS 16"：完整路线图

> 起点：探针 **117 命中**（2026-11-22 00:17）—— 内核已启动调度器、第一个内核线程在跑。
> 终点定义见 §0。每一阶段都写了「输入 / 关键工作 / 怎么算成了 / 参照 / 估算」。
>
> **估算单位是"轮"**：一轮 = 改补丁 → 构建（约 13 分钟）→ 刷机 → 拍屏 → 判读（约 20–30 分钟）。
> 估算是按参照项目的实际完成度推的，不是承诺。

---

## 0. "完美运行"的现实定义

先把话说明白，避免后面反复：

| 目标 | 可行性 | 依据 |
|---|---|---|
| 开机进 SpringBoard、桌面、图标、设置 | ✅ 有先例 | 小米 8（iOS 16.5）、fajita（iOS 16.5）、raphael（iOS 16.7.16 / iPadOS 17.7.11） |
| 触摸、亮度、音量键、振动、手电筒 | ✅ 有先例 | 同上 |
| Wi-Fi 上网、Safari | ✅ 有先例 | 小米 8（WCN3990）、fajita |
| GPU 加速（60 fps 级） | ⚠️ 有先例但极难 | fajita 的 Adreno 630 做到 60 fps；**SDM660 的 Adreno 512 没有人做过** |
| 扬声器 / 麦克风 / 蓝牙 | ⚠️ 有先例 | 小米 8 走 ADSP + TAS2557 |
| LTE 数据 | ⚠️ 有先例 | fajita（只有数据，语音无公开证据） |
| **打电话（语音）** | ❓ 无公开证据 | 需要 IMS/VoLTE 或 CS fallback，未见项目做到 |
| 相机、传感器、指纹 | ❌ 基本不可能 | 闭源 HAL、无公开驱动 |
| App Store / iCloud / 推送 | ❌ 不可能 | 需要 Apple 设备签名与服务器认证 |
| 长期稳定、省电 | ❌ 不在可达范围 | 所有项目都标注"不适合日常使用" |

**结论**：现实的终点是「**能开机进桌面、能触摸、能上网、部分外设可用，但离日常使用仍有距离**」。
下面所有阶段都朝这个终点排。

## 2. 各阶段细节

### P0 内核启动收尾（当前）　10–25 轮

**输入**：117 已命中。

**关键工作**：按顺序推进 `kernel_bootstrap_thread()` 的剩余调用：

| 探针 | 调用 | 风险 |
|---|---|---|
| 118 | `thread_daemon_init()` | 低 |
| 119 | `kernel_startup_initialize_upto(THREAD_CALL)` | 中（hooks 内部可能碰 Apple 硬件） |
| 120 | `thread_bind(processor)` | 低 |
| 121 | `mapping_adjust()` | 中（VM 映射） |
| 122 | `clock_service_create()` | **高**（要 `mach_absolute_time` 与设备树时钟） |
| 123 | `device_service_create()` | **高**（设备树 + IOKit） |
| 124 | `phys_carveout_init()` | 中 |
| 125 | `kdp_init()` | 中（串口调试协议） |
| 126 | `kernel_startup_initialize_upto(SYSCTL)` | 中 |
| 127 | `vm_kernel_addrperm = early_random()` | 低 |
| 128 | `PE_init_iokit()` | **需跳过**（Apple 平台代码，同 `PE_init_cpu`） |
| 129 | `kernel_startup_initialize_upto(EARLY_BOOT)` | 中 |

**怎么算成了**：129 之后不崩，且 `assert(ml_get_interrupts_enabled() == FALSE)` 通过。

**参照**：HakiOS 的 `arm_init`/`kernel_bootstrap` 补丁（我们已经在用它）。

---

### P1 内核完整初始化　15–30 轮

**关键工作**：

1. **真正打开中断**（到目前为止一次都没开过）：GIC 初始化 + 投递路径。注意内核早就报过
   `pe_arm_map_interrupt_controller: failed to find the interrupt-controller` —— ADT 里没有 XNU
   期望的中断控制器节点，要么补节点，要么让 GIC 路径容错。
2. **定时器**：`clock_service_create` 之后要有可用的 tick。
3. **`machine_init()` 里剩下的平台钩子**。
4. **KDP / 串口**：如果 P1 期间能把 UART 控制台做出来（并行会话的 `sdm660_uart` 就是干这个的），
   后面所有阶段的迭代速度会翻几倍 —— **这是投产比最高的一个支线**。

**怎么算成了**：内核能稳定跑到 `bsd_init()` 门口，中途能响应中断。

---

### P2 存储与根卷　20–40 轮

**关键工作**：

1. **eMMC 驱动**：SDM660 用 SDHCI/ICE 那套；`linux-drivers/mmc` 有参考
2. **读 GPT**：拿到 Meizu 15 的真实分区表
3. **根卷**：两条路
   - `APFS` 读写（clover 正在做"APFS probes"）
   - `mockfs`（clover 已用：eMMC 后端 + 内存文件系统，先跑通再换 APFS）
4. **iOS 系统卷**：需要 Apple 的 `SystemOS`/`Data` 卷（从 IPSW 提取，或按 raphael 那条路）

**怎么算成了**：能挂载根卷、能读到 `/System/Library/` 下的文件。

**参照**：`qine233/UniXNU-clover`（SDM660 + eMMC + mockfs）、`appleiPodTouch4/UniXNU-r11`。

---

### P3 `bsd_init` + launchd　30–60 轮

**关键工作**：

1. **Mach IPC / bootstrap**：launchd 靠 Mach ports 活
2. **BSD 层子系统**：VFS、`proc`、`kqueue`、`ucred`、socket 域
3. **平台 expert**：`IODTPlatformExpert` 那套；`PE_init_iokit` 的位置要换成自己的实现
4. **launchd 启动**：`/sbin/launchd` 跑起来、`launchd.plist` 解析、服务注册

**怎么算成了**：`launchd` 进程存在，`sysctl` 能看到基本服务。

**参照**：小米 8 / fajita 都到了"launchd 及系统服务运行"。

---

### P4 显示（CPU 呈现）　15–30 轮

**关键工作**：

1. **MDSS/DSPP 初始化**：SDM660 的显示控制器；面板时序从 ADT 或 Android 的 `dtb` 拿
2. **Framebuffer**：先做 UEFI 继承的 framebuffer（payload 已经有），或自己分配
3. **`MiniIOMobileFramebuffer` 移植**：`drawLayer` / `present` / `SwapEnd`
4. **`MiniIOSurface`**：CPU 侧的 surface 管理

**怎么算成了**：屏幕出现 Apple Logo，然后是 Hello / 设置向导。

**参照**：**OPPO R11**（同 SDM660、同 1080×1920 AMOLED）、小米 10（CPU framebuffer 显示 Hello）。

---

### P5 SpringBoard + 触摸　10–20 轮

**关键工作**：

1. **SpringBoard 启动**：iOS 16 的窗口服务器
2. **CoreAnimation 软件渲染**（默认路径）：HakiOS 文档说软件渲染 15–40 fps
3. **触摸驱动**：Meizu 15 用的是哪颗触摸 IC 需要确认（R11 是 Synaptics，小米 8 是 FTS）
4. **手势**：滑动、点击

**怎么算成了**：能滑动解锁、能进桌面、能点图标。

**参照**：小米 8、fajita、raphael（都到了桌面/锁屏）。

---

### P6 外设　40–100 轮

按"投入产出比"排序：

| 顺序 | 外设 | 参照 | 说明 |
|---|---|---|---|
| 1 | **Wi-Fi** | 小米 8（WCN3990） | SDM660 是 WCN3990 同系？需确认；有固件加载 + cfg80211 那套 |
| 2 | **音频（扬声器）** | 小米 8（ADSP + TAS2557） | 走 ADSP 的 ASM/ADM/AFE 通路 |
| 3 | **蓝牙** | 小米 8 | 与 Wi-Fi 同芯片，串口/HS 传输 |
| 4 | 麦克风、音量键、振动、手电筒 | 小米 8 | 相对简单 |

---

### P7 GPU 加速　30–60 轮

**关键工作**：

1. **`hakios.adreno.c` 从 a6xx 改到 a5xx**：
   - ring / 微码布局（a5xx 没有 a6xx 的 GMU 预emption，启动流程短）
   - 寄存器初始化序列（`CP_ME_INIT` 那套）
   - SMMU 版本（SDM660 = SMMU-500，与 SDM845 同代）
2. **`HakiosGPU` 接口**（DRM 风格请求 0x7d/0x7e）基本可以照搬
3. **`MiniIOSurface` + `MiniIOMobileFramebuffer`** 接上 GPU buffer
4. **用户态**：Mesa freedreno（**a5xx 已被 Linux 社区充分支持**）→ OpenGL ES 路径先通
5. 可选：`hakios-metal`（AIR → NIR → ir3）追求 60 fps

**怎么算成了**：CoreAnimation 走 GLES 渲染，滑动流畅（>30 fps）。

**风险**：**没有任何人在 Adreno 512 上做过这件事**。这是整条路线里唯一"没有先例"的环节。

---

### P8 蜂窝　60–150 轮

**关键工作**（照 HakiOS `cellular.md` 的层次）：

1. **MPSS 启动**：TrustZone 固件、共享内存、SMP2P、GLINK、QRTR
2. **RMTFS**：eMMC 分区当 modem 文件系统（只读）
3. **IPA**：包引擎固件、时钟、SMMU、`INIT_DRIVER` 握手
4. **QMI 服务**（88 个）→ SIM 识别 → NAS 注册 → 信号
5. **数据会话**：QMAP mux、IPv4、DNS/MTU
6. **语音**：无公开先例，需要 IMS/VoLTE 或 CS fallback

**怎么算成了**：状态栏有信号格、能上网。（语音另算）

---

### P9 稳定化　持续

长期运行、省电、死机恢复、温度控制。所有参照项目都明确写着"不适合日常使用"，
这一阶段没有终点。

## 3. 并行支线（不阻塞主线的两件事）

### 3.1 UART 串口控制台（最高优先级的支线）

**为什么**：现在每轮迭代都要"拍屏 → 人读 → 我判读"，一次 20–30 分钟。
串口控制台能把内核日志实时抓到电脑上，**直接消灭这个瓶颈**。

**现状**：并行会话已经在写 `kernel/sdm660/`（`sdm660_uart.c`：QUP GENI 与 8250 两种布局），
默认关闭（`sdm660_shim=1`），不干扰现有探针。

**代价**：需要一根 USB-TTL 或利用现有的 UART 引出（Meizu 15 主板上有测试点）。

### 3.2 双系统引导菜单（L1）

在 `Meizu15Launcher` 里加 "Boot Android"（实现 Linux arm64 boot protocol）。
不刷分区、可逆。**建议排在 P4 之后**（等 iOS 侧能看到画面了才有意义）。

## 5. 三个决定性风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| **P7 无先例** | Adreno 512 上没人跑过 XNU 的 GPU 栈 | 先做 CPU 呈现（P4/P5 不依赖 GPU）；freedreno 的 a5xx 支持是现成的 |
| **P2/P3 的根卷** | 没有 Apple 的系统卷就没有 SpringBoard | 参考 clover 的 mockfs 路线；或从 IPSW 提取 |
| **拍屏瓶颈** | 每轮 20–30 分钟里有一半耗在"人读屏幕" | **3.1 的串口控制台**是根本解法，优先级应该提前 |
